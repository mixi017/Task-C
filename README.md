# Разбор кода: почему `Foo` всегда возвращает `false`

## Исходный код

Исходный код задачи: [task_c/source.c](https://github.com/mixi017/Task-C/blob/main/task_c/source.c)

## 1. Добавить необходимые заголовочные файлы

```c
#include <stdbool.h> // для типа bool
#include <stdio.h>   // для printf()
```

## 2. Сократить функцию `Foo`

Функцию можно сократить до такого вида (работать будет одинаково):

```c
bool Foo(UINT8 buff[6])
{
	return (buff[2] == -1);
}
```

## 3. Компиляция под Windows

Я попробовала скомпилировать код под Windows.

Компилятор со стандартными настройками решил, что раз `Foo()` принимает массив,
то передаваться в неё будет адрес, и преобразовал `0xFFFFFFFFFFFF` к типу указателя.
В результате в рантайме была получена **ошибка доступа к памяти**:
мы попытались прочитать, что лежит по смещению 2 от вымышленного адреса `buff[2]`.

```c
int main()
{
	if (Foo(0xFFFFFFFFFFFF)) { printf("true"); }
	else { printf("false");}
}
```

`0xFFFFFFFFFFFF` это 48 бит, в MSVC тип `__int64`.
Передача его в параметр-указатель без каста не соответствует стандарту C.
MSVC даёт только предупреждение (**C4047**), поэтому код компилируется,
но выдаёт ошибку во время выполнения.

## 4. Передать настоящий массив

Я переписала вызов функции, передав настоящий массив:

```c
UINT8 arr[6] = {0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF};
Foo(arr);
```

Падение исчезло, но программа всё равно выводит `false` (см. п. 5).

## 5. Почему выводится `false`

- Литерал `-1` имеет тип `int` и равен `0xFFFFFFFF`.
- Значение `buff[2]` имеет тип `unsigned char` (`0xFF`) и перед сравнением
  повышается до `int` (integer promotion): с 8 до 32 бит, старшие 24 бита
  заполняются нулями, получается `0x000000FF`, то есть `255`.

| Выражение | Значение |
|-----------|----------|
| `buff[2]` после повышения | `255` |
| `-1` | `-1` |
| `255 == -1` | `false` |

Проверка не пройдёт: `-1` не равно `255`, будет выведено `false`.

## Вывод

Из-за integer promotion (расширения до `int`) `buff[2]` всегда лежит
в диапазоне `0..255`, поэтому `buff[2] == -1` **никогда не истинно**.
Значит, `Foo` всегда возвращает `false` независимо от содержимого массива.
