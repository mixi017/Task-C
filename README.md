2. Функцию Foo можно сократить до такого состояния (будет работать одинаково)

bool Foo(UINT8 buff[6])
{
	return (buff[2] == -1);
}



3. Я попробовала скомпилировать под виндовс.
Компилятор со стандартными настройками решил, что если Foo() принимает массив,
то передаваться в неё будет адрес и преобразовал 0xFFFFFFFFFFFF к типу ptr.
В результате в рантайме была получена ошибка доступа к памяти, 
так как мы попытались посмотреть,
что лежит через 2 смещения от вымышленного адреса buff[2]

int main()
{
	if (Foo(0xFFFFFFFFFFFF)) { printf("true"); } 
	else { printf("false");}
}

0xFFFFFFFFFFFF это 48 бит, в MSVC тип __int64. 
Передача его в параметр-указатель без каста не соответствует стандарту C. 
MSVC даёт только предупреждение (C4047), поэтому код компилируется,
но выдаёт ошибку во время выполнения.



4. Я переписала вызов функции, передав настоящий массив

UINT8 arr[6] = {0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF};
Foo(arr);

Падение исчезло, но программа всё равно выводит false (см. п.5).



5. Литерал -1 имеет тип int и равен 0xFFFFFFFF. 
Значение buff[2] имеет тип unsigned char (0xFF),
и перед сравнением оно повышается до int (integer promotion): 
с 8 до 32 бит, старшие 24 бита заполняются нулями. 

проверка не пройдёт, -1 не равно 255, будет выведено false



Вывод. Из-за integer promotion (расширение до инта) 
buff[2] всегда лежит в диапазоне 0..255, 
поэтому buff[2] == -1 никогда не истинно. 
Значит, Foo всегда возвращает false, 
независимо от содержимого массива.
